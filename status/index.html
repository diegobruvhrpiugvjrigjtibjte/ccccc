HWTRS is built around a simple promise: keep encryption local, transparent, and under your control. This page explains a specific part of the platform, but it follows the same core principles across every area. Files never leave the device, and there are no accounts, trackers, or hidden services. We use AES-256-GCM for confidentiality and integrity, and PBKDF2 to derive strong keys from user passwords. The result is a secure .hwtrs archive that can be shared without exposing the contents. Security depends on the quality of the password and the health of the device, so we recommend strong phrases and trusted hardware. If the password is lost, recovery is impossible by design, because zero-knowledge must remain absolute. This page also outlines what the system can and cannot protect against, so expectations are clear. The browser environment has limits in memory and performance, especially with large files, and we openly document those limits. Transparency matters: the logic is auditable, the format is predictable, and the workflow is repeatable. HWTRS is not a cloud and does not replace backups; it is a privacy-focused tool for local encryption. Use it for documents, private archives, or secure file transfers, and keep separate backups in safe locations. We provide clear documentation to help users understand risks, best practices, and operational details. This page is part of a broader knowledge base intended to build trust through honest explanations. If you need support or have questions, contact the team for guidance and responsible disclosure.
