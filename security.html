Sicurezza

Threat model, limiti e promesse reali della cifratura client-side.

Panoramica della sicurezza

HWTRS è progettata per proteggere i file in contesti reali: condivisione di documenti sensibili, archiviazione personale, backup locale o invio di file cifrati tramite canali non affidabili. La cifratura avviene interamente nel browser con AES-256-GCM e una chiave derivata da password tramite PBKDF2. Non esistono server o API che possano essere compromessi, e la superficie di attacco è ridotta al dispositivo dell’utente.

La filosofia è zero-knowledge: nessuno, a parte l’utente con la password corretta, può accedere ai contenuti. Questo approccio elimina i rischi legati alla custodia centrale dei dati e semplifica il modello di fiducia.

Threat model: cosa protegge

HWTRS protegge i file se l’archivio .hwtrs viene intercettato, copiato o condiviso con terze parti. Senza la password corretta, il contenuto rimane cifrato e non leggibile. AES-256-GCM garantisce anche l’integrità dei dati, bloccando modifiche non autorizzate al payload.

La derivazione della chiave con PBKDF2 e 300.000 iterazioni rallenta gli attacchi a forza bruta. Questo rende impraticabile la decifrazione senza una password robusta, soprattutto se combinata con una lunghezza adeguata.

Threat model: cosa non protegge

HWTRS non può proteggere i file se il dispositivo è compromesso. Malware, keylogger o estensioni malevole possono intercettare i dati prima della cifratura o dopo la decifratura. Inoltre, una password debole o condivisa in modo improprio annulla la protezione.

Non essendo un servizio cloud, HWTRS non sincronizza i file tra dispositivi e non fornisce ridondanza automatica. La sicurezza dipende dall’utente e dalle sue pratiche di backup.

Zero-knowledge spiegato bene

Zero-knowledge significa che il sistema non può tecnicamente leggere i dati che processa. In HWTRS, la cifratura avviene localmente nel browser e la password non viene mai inviata o salvata. Questo elimina il rischio che un server esterno possa accedere ai tuoi file, anche in caso di attacco.

È un modello ideale per chi vuole mantenere il pieno controllo dei propri dati, accettando la responsabilità di gestire in modo corretto la password e i backup.

Limiti del browser

La cifratura avviene in RAM. File molto grandi possono rallentare o causare instabilità in dispositivi con poca memoria. HWTRS impone un limite di 150MB per mantenere un’esperienza affidabile. È un compromesso tra performance e accessibilità, pensato per l’uso quotidiano.

Se lavori con dataset più grandi, consigliamo di dividere i file in più archivi o di utilizzare dispositivi con maggiore RAM disponibile.

Password e recupero

La password è l’unica chiave di accesso. Se viene persa, non esistono procedure di recupero o backdoor. Questa scelta è coerente con la filosofia zero-knowledge e garantisce che nessuno possa accedere ai tuoi dati senza autorizzazione esplicita.

Per questo motivo consigliamo l’uso di un password manager o la conservazione sicura della password in un canale protetto.
